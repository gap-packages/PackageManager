1 PackageManager Documentation

PackageManager allows you to install and remove GAP packages on your system quickly and easily with a single command. The main functionality is provided by the following commands:

  • InstallPackage (1.3-1) to install a package by its name, or by a URL to an archive, Git repository or package info file.

  • RemovePackage (1.3-2) to remove a package by its name.

  • InstallRequiredPackages (1.3-4) to install all the packages that GAP needs in order to run.

Compiling the package, building the documentation, and installing dependencies are all handled automatically.

The behaviour of PackageManager can be customised in various ways by setting appropriate user preferences, as described in Section 1.4. These can also be overridden for a single call by adding an optional argument prefs to the appropriate function call, as described in the documentation for the InstallPackage (1.3-1) command.

By default, packages will be installed in the pkg subdirectory of GAPInfo.UserGapRoot (see Reference: GAP Root Directories). Note that this location is not the default user pkg location on Mac OSX, but it will be created on any system if not already present. Note also that starting GAP with the -r flag will cause all packages in this directory to be ignored.

1.1 Basic usage

PackageManager is distributed with GAP, so it should already be available on your system. If it is not already loaded, you can call it with:

gap> LoadPackage("PackageManager");

To install the latest deposited version of the Digraphs package, use the following:

gap> InstallPackage("digraphs");

To uninstall it later, use the following:

gap> RemovePackage("digraphs");

You can also

PackageManager also supports version control repositories. To install the latest version of the curlInterface package from GitHub, use the following:

gap> InstallPackage("https://github.com/gap-packages/curlInterface.git");

1.2 Changes in version 2.0

PackageManager 2.0 changed several ways that the introduced a range of new features, including the ability to download the structured info for the whole package distribution, and plan dependency trees in advance before installation begins. It also introduced a range of user preferences, which are described under the InstallPackage (1.3-1) command below.

1.3 Commands

1.3-1 InstallPackage
‣ InstallPackage( string[, prefs] )( operation )

Returns: true or false

Attempts to download and install a package. The argument string should be a string containing one of the following:

  • the name of a package;

  • the URL of a package archive, ending in .tar.gz or .tar.bz2;

  • the URL of a git repository, ending in .git;

  • the URL of a valid PackageInfo.g file.

The package will then be downloaded and installed, along with any additional packages that are required in order for it to be loaded. Its documentation will also be built if necessary. If the installation is completed successfully, or if this package is already installed, true is returned; otherwise, false is returned.

gap> InstallPackage("digraphs");
#I  The following packages will be installed:
#I    Digraphs        1.15.0
#I    orb             5.1.0
#I    datastructures  0.4.3
Continue? [Y/n] y
true

This command's behaviour is affected by the user preferences that have been set for the PackageManager package. These can be updated using, for example, SetUserPreference("PackageManager", "compile", true); but these can also be overridden for this call by using the optional second argument prefs for this function, for example InstallPackage(name, rec(compile := false));

The available preferences are as follows:

  • dependencies - whether to install the package's dependencies as well

  • suggested - whether to include suggested as well as required dependencies

  • compile - whether to attempt to compile newly installed packages

  • compileDeps - whether to attempt to compile the dependencies of newly installed packages

  • upgrade - whether to upgrade already installed packages if an upgrade is available

  • git - whether to attempt to pull from Git repos when upgrading

  • proceed - whether to proceed with the installation at all (after printing the installation plan)

  • interactive - set this to false to disable all interactive prompting (preferences set to "ask" are instead treated as true)

  • distroLocation - the URL to download the GAP package distribution info from

  • distroVersion - the version of the package distribution info to use (choose a version of GAP, or just "latest")

  • version - the version of a particular package to attempt to install

  • branch - the name of the branch to attempt to install when using a Git repo (or fail for the default branch)

All boolean preferences above (those described as "whether to...") can be set to true, false, or "ask" which will prompt the user interactively. This is the default setting for many of them.

gap> InstallPackage("profiling", rec(interactive := false,
>                                    suggested := true,
>                                    compileDeps := false));
#I  The following packages will be installed:
#I    profiling  2.6.3
true

To see more information about the install process while it is ongoing, see InfoPackageManager (1.5-1).

If the version preference is specified, then it is interpreted as described in Section Reference: Version Numbers. In particular, the value will be treated as a minimum version number unless it starts with =.

If installation fails, then any new directories that were created will be preserved. To remove them, the RemovePackage (1.3-2) operation can be used.

1.3-2 RemovePackage
‣ RemovePackage( name[, prefs] )( operation )

Returns: true or false

Attempts to remove an installed package using its name. The first argument name should be a string specifying the name of a package installed in the user GAP root, see Reference: GAP Root Directories.

This command's behaviour is affected by the user preferences that have been set for the PackageManager package. These can be set globally, or overridden for this command using the optional prefs argument, in the same way as for the InstallPackage (1.3-1) command.

Returns true if the removal was successful, and false otherwise.

gap> RemovePackage("digraphs");
Really delete directory /home/user/.gap/pkg/digraphs-0.13.0 ? [y/N] y
true

1.3-3 CompilePackage
‣ CompilePackage( name[, prefs] )( operation )

Returns: true or false

Attempts to compile an installed package. Takes one argument name, which should be a string specifying the name of a package installed in the user GAP root (for example, one installed using InstallPackage (1.3-1)), see Reference: GAP Root Directories. Compilation is done automatically when a package is installed or updated, so in most cases this command is not needed. However, it may sometimes be necessary to recompile some packages if you update or move your GAP installation.

Compilation is done using the etc/BuildPackages.sh script bundled with PackageManager. If the specified package does not have a compiled component, this function should have no effect.

This command's behaviour is affected by the user preferences that have been set for the PackageManager package. These can be set globally, or overridden for this command using the optional prefs argument, in the same way as for the InstallPackage (1.3-1) command.

Returns true if compilation was successful or if no compilation was necessary. Returns false otherwise.

gap> CompilePackage("digraphs");
#I  Running compilation script on /home/mtorpey/.gap/pkg/datastructures-0.4.3/ ...
#I  Running compilation script on /home/mtorpey/.gap/pkg/orb-5.1.0/ ...
#I  Running compilation script on /home/mtorpey/.gap/pkg/io-4.10.0/ ...
#I  Running compilation script on /home/mtorpey/.gap/pkg/digraphs-1.15.0/ ...
true
gap> CompilePackage("profiling", rec(compileDeps := false));
#I  Running compilation script on /home/mtorpey/.gap/pkg/profiling-2.6.3/ ...
true

1.3-4 InstallRequiredPackages
‣ InstallRequiredPackages( [prefs] )( operation )

Returns: true or false

Attempts to download and install the latest versions of all packages required for GAP to run. Currently these packages are GAPDoc, PerfGrp, PrimGrp, SmallGrp, and TransGrp. Returns false if something went wrong, and true otherwise.

Clearly, since these packages are required for GAP to run, they must be loaded before this function can be executed. However, this function installs the packages in the ~/.gap/pkg directory, so that they can be managed by PackageManager in the future, and are available for other GAP installations on the machine.

This command's behaviour is affected by the user preferences that have been set for the PackageManager package. These can be set globally, or overridden for this command using the optional prefs argument, in the same way as for the InstallPackage (1.3-1) command.

1.3-5 RefreshPackageMetadata
‣ RefreshPackageMetadata( [prefs] )( operation )

Returns: true or false

Attempts to download metadata for all available packages from the GAP package distribution.

Calling this function is not usually necessary, since the metadata is downloaded automatically the first time InstallPackage (1.3-1) is called, and the result is cached for the rest of the GAP session. However, this function can be called to force the download and retrieve any updated information.

Returns false if something went wrong, and true otherwise.

This command's behaviour is affected by the user preferences that have been set for the PackageManager package. These can be set globally, or overridden for this command using the optional prefs argument, in the same way as for the InstallPackage (1.3-1) command.

1.4 User Preferences

PackageManager exposes several user preferences which can be set to customise the behaviour of the package globally. For example, calling

gap> SetUserPreference("PackageManager", "compile", false);

will make it so that new packages are not compiled automatically when InstallPackage is called for the rest of the session. You could instead specify this as a one-off by passing a record to the command, as follows:

gap> InstallPackage("digraphs", rec(compile := false));

You can make your preferences persist between sessions by calling WriteGapIniFile (Reference: WriteGapIniFile) and finding the settings in your gap.ini file.

A full list of user preferences recognised by the package is described in the documentation for InstallPackage (1.3-1).

1.5 Info Warnings

1.5-1 InfoPackageManager
‣ InfoPackageManager( info class )

Info class for the PackageManager package. Set this to the following levels for different levels of information:

  • 0 - No messages

  • 1 - Problems only: messages describing what went wrong, with no messages if an operation is successful

  • 2 - Directories and versions: also displays information about installation directories and package versions

  • 3 - Progress: also shows step-by-step progress of operations

  • 4 - All: includes extra information such as whether curlInterface is being used, package info validation and compilation output

Set this using, for example SetInfoLevel(InfoPackageManager, 1). The default value is 3.
